🛡️ Pilar 1: Governança e Segurança de Dados
• O Escudo (.gitignore): Nunca suba dados brutos (CSVs) para o GitHub. Use o .gitignore para manter o repositório seguro contra vazamentos de dados sensíveis.

• Hierarquia de Pastas: Pastas como `data/` (ignorada) e `scripts/` (versionada) separam a "matéria-prima" da "inteligência do negócio".

🧬 Pilar 2: Fluxo de Trabalho (Git Flow)
• Isolamento de Riscos (Branches): Sempre que for mudar uma lógica central, crie uma branch (ex: `refactor/`). Se o código "quebrar", a versão estável na `master` permanece protegida.

• A Regra da Precisão: Nomes de branches e commits exigem atenção absoluta. Erros como `sutentabilidade` ou `CO1` afetam a imagem profissional.

• Sincronização (Merge & Push): O trabalho só existe para o mundo quando está no GitHub. Use o push como o marco final de um bloco de estudo produtivo.

📊 Pilar 3: Raciocínio Analítico e Científico
• Lógica de Dados (SQL): Use `SELECT` para filtrar e `WHERE` para identificar gargalos críticos. Multiplicar por `1.0` evita erros de arredondamento em divisões.

• Documentação em LaTeX: Fórmulas no README elevam o nível do portfólio (ex: ).

⏱️ Pilar 4: Gestão de Foco e Produtividade
• GitHub Issues: Antes de começar, crie uma Issue. Ela serve como "âncora" de atenção contra as distrações (redes sociais).

• Fechamento de Ciclo: O ritual de fechar a Issue e deletar a branch gera satisfação e conclui o bloco de estudo.

• Teclado vs. Mouse: Use o terminal e atalhos. Quanto menos usar o rato, mais difícil é a transição mental para o telemóvel.
